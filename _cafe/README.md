# 카페 자동 글쓰기 대기열 (폰안파는폰가게 · cafe.naver.com/mamn9)

이 폴더는 사이트에 공개되지 않는다(_로 시작). 매일 예약 작업이 새 글 3개를 여기에 넣고,
사용자 PC(C:\autowin)의 프로그램이 09:00에 내려받아 09:00~11:40 사이 랜덤 시각에 카페에 올린다. 매일 작성은 09:00 전에 끝나야 한다.

## 폴더 구조
- index.json: 전체 글 목록 (folder, keyword, type, model, created, files). 새 글은 posts 배열 끝에 추가. 기존 항목은 고치거나 지우지 않는다.
- posts/<폴더>/post.json, card1.html, card2.html, img1.png, img2.png
- 폴더 이름: c + 3자리 번호(이어서) + _ + 영문 소문자·숫자·하이픈 (예: c004_galaxy-s26-spec). 한글 금지.
- tools/render.py: cardN.html → imgN.png 렌더링
- 게시판: PC 프로그램이 app/cafe_config.json 의 boards(스마트폰 정보, 휴대폰 공동구매, 문의게시판, 가입인사, 설치후기, 현금사은품지급 명단) 중 올린 글이 가장 적은 곳을 골라 올린다(게시판별 노출 비교용). 글은 게시판과 상관없이 같은 정보글 규칙으로 쓰고, post.json 에 board 를 넣지 않는다.

## post.json 형식
{"keyword": "...", "title": "...", "body": ["문단", {"image": "img1.png"}, "문단", ...], "tags": ["띄어쓰기없는태그", ...]}
- body 문자열 하나 = 한 문단. 문단 안 줄바꿈은 \n. 소제목은 "■ "로 시작.
- {"image": "imgN.png"} 위치에 사진이 들어간다. 사진은 2장, 서로 떨어진 위치에.
- tags 4개, 띄어쓰기 없이. 1번 = 키워드 붙여 쓴 것.
- 분량: 문단 6~8개, 본문 900~1,300자.

## 키워드 규칙 (사용자 지정)
- 성지 내용 금지. 휴대폰·핸드폰 싸게 사는 법, 휴대폰·IT 생활 정보 위주.
- 하루 3개 구성: **모델 키워드 2개 + 생활 IT 1개** (A·C에서 2개, B에서 1개).
  모델 키워드 2개 중 1개는 이틀에 한 번꼴로 C(출시 예정폰)로 쓴다. 출시·사전예약 시기가 가까운 모델이 있으면 더 자주.
  단, 최근 1~2일 안에 큰 IT 뉴스가 있으면 그날은 B 자리를 뉴스로 쓴다.

### A. 모델 키워드 (주력, 하루 2개)
- 4유형: 모델명+가격 / 모델명+스펙 / 모델명+자급제 / 모델명+유심기변.
  가끔 대신: 모델명 vs 모델명 비교.
- 2개는 서로 다른 유형·다른 모델. 같은 모델은 3일 안에 반복하지 않는다(C의 출시 예정폰은 같은 모델이라도 유형이 다르면 2일 간격 허용).
- 현재 국내 판매 중인 모델을 고루 돌린다: 갤럭시 S26/S26+/S26 울트라, 갤럭시 Z 폴드·플립 최신, 갤럭시 A 시리즈(A37, A57 등), 아이폰 17, 아이폰 에어, 아이폰 18 프로/프로 맥스, 아이폰 17e 등. 판매 여부는 검색으로 확인.
- 경쟁이 덜한 세부 형태도 섞는다(예: 갤럭시a57 자급제 가격).

### C. 출시 예정 스마트폰 (모델 키워드 자리에 섞어 씀)
- 4유형: 출시예정폰이름+출시일 / 출시예정폰이름+사전예약 / 출시예정폰이름+가격 / 출시예정폰이름+스펙.
  예) "갤럭시s27 출시일", "갤럭시s27 사전예약", "아이폰18 가격", "갤럭시z폴드8 스펙".
- 대상: 국내 출시 예정이 공식 발표됐거나 주요 언론에 반복 보도된 모델만. 모델명은 사람들이 실제 검색하는 표기로.
- 확정 정보(공식 발표)와 예상·루머(유출, 업계 전망)를 문장마다 분명히 구분한다. "예상", "보도에 따르면", "공식 발표 전"을 붙이고 확정처럼 쓰지 않는다.
  가격은 공식 발표 전이면 "예상 가격(○○ 보도 기준)"과 전작 출고가 비교로만 쓴다. 출시일·사전예약 일정은 확정과 예상을 표로 나눠 보여 준다.
- 사전예약 글: 일정, 사전예약 혜택(공식 발표된 것만), 자급제·통신사 사전예약 차이, 준비할 것. 이미 출시된 모델이면 A의 가격·자급제 글로 바꾼다.
- 같은 모델의 C 4유형은 순서대로(출시일 → 스펙 → 가격 → 사전예약) 쓰되, 실제 일정이 가까워지면 사전예약을 앞당긴다.

### B. 생활 IT (하루 1개, 아래 5종을 돌려 가며 — 같은 종류는 4일 안에 반복하지 않는다)
1. 최신 IT 뉴스: 최근 1주일(가능하면 1~2일) 휴대폰·통신·IT 뉴스 중 사람들이 바로 검색할 주제.
   제조사·통신 3사·정부 발표, 할인 행사, 신제품 공개·출시·사전예약, 요금제·지원금 변경, 장애·보안 사고 등.
   키워드는 행사 공식 이름보다 검색창에 치는 생활어로(예: "SKT 요금제 개편", "삼성 휴대폰 할인").
   본문에 발표 날짜·보도 매체를 밝히고 "그래서 나는 뭘 하면 되나"로 마무리. 같은 뉴스로 두 번 쓰지 않는다.
2. 카카오톡 꿀팁: 예) "카카오톡 대화 백업 안될때", "카카오톡 멀티프로필 확인 방법", "카톡 읽씹 안 들키게". 최근 업데이트로 생긴 기능 우선.
3. 안드로이드(갤럭시) 업데이트·꿀팁: 예) "One UI 8 업데이트 후 배터리", "갤럭시 통화 녹음 방법", "갤럭시 저장공간 정리".
4. iOS(아이폰) 업데이트·꿀팁: 예) "iOS 26 업데이트 오류", "아이폰 배터리 성능 확인", "아이폰 사진 용량 줄이기".
5. 윈도우 꿀팁: 예) "윈도우 11 화면 캡처 단축키", "윈도우 업데이트 끄기", "윈도우 느려질때".
- 꿀팁은 "~안될때", "~오류", "~방법"처럼 증상·목적형 키워드를 우선하고, 단계별 따라 하기(1, 2, 3…)와 상태별 분기를 넣는다.
- 메뉴 경로·버튼 이름은 공식 도움말(카카오 고객센터, 삼성 멤버스·삼성전자 고객지원, 애플 지원, 마이크로소프트 지원) 또는 신뢰할 수 있는 최근 자료로 확인한 것만 따옴표로 쓴다. 버전에 따라 다르면 기준 버전을 밝힌다.
- 업데이트 글은 공식 배포 여부·대상 기기·배포 시작일을 확인하고, 루머는 "예상"으로 구분한다.

### 공통
- **모델명은 띄어쓰지 않고 붙여 쓴다 (사용자 지정).** 브랜드+모델 번호를 붙이고 영문은 소문자:
  갤럭시s26, 갤럭시s26울트라, 갤럭시s26+, 갤럭시z플립8, 갤럭시z폴드7, 갤럭시a57, 아이폰17, 아이폰17e, 아이폰17프로, 아이폰18프로맥스, 아이폰에어.
  키워드·제목·본문·태그 모두 적용. 키워드 예: "갤럭시s26 가격", "아이폰17 자급제" (모델명 뒤 단어와는 띄어쓰기).
  글을 다 쓴 뒤 반드시 python3 _cafe/tools/nospace.py _cafe/posts/<폴더> 를 실행해 남은 띄어쓰기를 정리한다.
- 같은 키워드는 다시 쓰지 않는다(index.json 확인). index.json 의 type 값: 가격/스펙/자급제/유심기변/비교/출시예정_출시일/출시예정_사전예약/출시예정_가격/출시예정_스펙/IT뉴스/카톡꿀팁/안드로이드/iOS/윈도우.
- 키워드는 제목 맨 앞에 띄어쓰기 그대로 + 본문 첫 문단 첫 문장에 1회 그대로. 본문 전체 3~5회.
- **제목은 짧게 (사용자 지정): 키워드 포함 25자 안팎(최대 28자), 한 줄.** "키워드, 핵심 한 마디" 형태로 쓰고 부제·말줄임(…)·두 문장 이어 붙이기 금지. 예) "갤럭시s26울트라 가격, 인상 후 용량별 정리"

## 내용 규칙
- 가격·스펙·출시일·정책은 반드시 웹 검색으로 확인한 최신값만 (제조사·통신사 공식, 주요 언론). 확인 못 한 수치는 쓰지 않는다. 본문에 "(2026년 M월 확인)"처럼 기준 시점 표기.
- 2026-10-01 갤럭시 S26 시리즈 출고가 14만9,600원 인상, 2026-09-10 아이폰 17 가격 인상(256GB 145만 원)·아이폰 17 프로/프로 맥스 애플 공식 판매 종료 등 최근 변동을 반영(재확인).
- 본문 끝에 출처 목록·고지 문구를 넣지 않는다. 브랜드(폰안파는폰가게) 홍보 문구는 넣지 않는다.
- 과장·재촉 표현 금지: 최저가, 무조건, 100%, 역대급, 지금 바로, 선착순, 공짜(근거 없이).
- 다른 매장·업체 비방 금지.
- 마지막 문단은 댓글로 질문 유도 등 자연스러운 마무리, 매번 문장을 다르게.
- 반복 콘텐츠 제재를 피하기 위해 구성을 매번 바꾼다: 표·목록형, Q&A형, 계산 예시형, 상황별 추천형, 순서 안내형, 비교형 등. 같은 날 3개 글은 구성도 서로 다르게. 첫 문장 패턴도 매번 다르게.

## 이미지 규칙 (card1.html, card2.html → img1.png, img2.png)
- 코드로 만든 정보 카드(무료). 너비 1080px 고정, 높이는 내용대로(700~1100px). 글꼴 'Noto Sans CJK KR'.
- 글마다 2장, 서로 다른 레이아웃. 매번 배경색·포인트색·레이아웃을 바꿔 이전 글들과 비슷해 보이지 않게(최근 posts의 card html을 보고 피한다).
  레이아웃 예: 가격표, 큰 숫자 계산, 2열 비교, 세로 타임라인, 체크리스트, 증상→해결 표, 스펙 아이콘 그리드, 질문 카드, 막대 비교 등.
- 제품 사진·로고·다른 사이트 이미지 금지. 꿀팁 글도 가짜 화면 캡처를 만들지 않는다(단계 순서도·체크리스트·증상→해결 표 등 도식으로). 이모지 금지(✓ 같은 기호는 가능). 글자 대비 충분히.
- <!doctype html> 로 시작(표 글자색 문제 방지). 외부 리소스 불러오지 않는다.
- 렌더링 후 이미지를 직접 열어 글자 겹침·잘림·안 보이는 글자가 없는지 확인하고 고친다.
